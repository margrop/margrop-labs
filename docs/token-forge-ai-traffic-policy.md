# Token Forge AI 流量与成本策略

P4-004 为 `token-forge.plan-v1` 定义 Provider-neutral 的预算、滑动限流、并发预留和熔断
核心。实现位于 `@margrop-labs/ai-gateway/token-forge-policy`，只操作经过验证的内存状态，
不创建 HTTP 端点、Provider Adapter、密钥、数据库或部署配置。

策略合同由
[`token-forge-ai-policy-v1.schema.json`](../schemas/token-forge-ai-policy-v1.schema.json)
约束。P1-008 的服务端端点必须先通过这层准入，再调用 Provider；任一拒绝都沿用 AI
Gateway 的安全失败信封并保留确定性模板计划。

## 固定硬边界

| 边界                                     |     默认硬上限 |
| ---------------------------------------- | -------------: |
| 单个 Gateway 请求可计费 Token            |         56,000 |
| 单个 Gateway 请求成本                    |          $0.10 |
| 匿名用户每日 Token                       |        224,000 |
| Token Forge 每日 Token                   |      2,240,000 |
| 全站每日 Token                           |      5,600,000 |
| 匿名用户每日成本                         |          $0.25 |
| Token Forge 每日成本                     |          $5.00 |
| 全站每日成本                             |         $10.00 |
| 匿名用户 / Token Forge / 全站每日请求    | 12 / 200 / 400 |
| 60 秒内匿名用户 / Token Forge / 全站请求 |    2 / 20 / 40 |
| 匿名用户 / Token Forge / 全站并发        |      1 / 4 / 6 |
| 预留有效期                               |          60 秒 |
| 连续失败后熔断                           |           5 次 |
| 熔断打开时间                             |          60 秒 |
| 半开探针                                 |           1 个 |

微美元是整数成本单位：`1 USD = 1,000,000 microUSD`，避免浮点金额累计误差。56,000
Token 覆盖 AI Gateway 最多两次 Provider 尝试的最坏情况，而不是只覆盖最终成功的一次。
如果 Labs 自己承担 Provider 费用，服务端价格表必须用固定模型价格和最大尝试次数计算预留
Token 与预留成本。P1-008 的自建上游网关承担货币预算，所以使用下述最小金额占位；浏览器
仍不能提交价格、模型、预留额或结算用量。

共享 Schema 和 Production 运行配置不能超过上述预算、频率、并发和失败阈值。若调整真实
模型、最大尝试次数或价格，必须先验证单次成本上限仍覆盖最坏情况，再发布配置。

## P1-008 生产配置

P1-008 针对自建 OpenAI-compatible 网关启用更保守的运行配置：

| 边界                                     |                           生产配置 |
| ---------------------------------------- | ---------------------------------: |
| 单模型输入 / 输出 / Gateway 尝试         |        22,000 / 2,000 Token / 1 次 |
| 主模型 / 顺序回退模型                    |       qwen-latest / minimax-latest |
| 共享 Provider 超时                       |                              45 秒 |
| 单请求预留                               | 48,000 Token / 1 microUSD 合同占位 |
| 匿名用户 / Token Forge / 全站每日 Token  |     96,000 / 1,200,000 / 2,400,000 |
| 匿名用户 / Token Forge / 全站每日请求    |                       4 / 50 / 100 |
| 60 秒内匿名用户 / Token Forge / 全站请求 |                         1 / 6 / 10 |
| 匿名用户 / Token Forge / 全站并发        |                          1 / 2 / 3 |
| 预留有效期                               |                              60 秒 |
| 连续失败 / 熔断打开时间 / 半开探针       |               3 次 / 120 秒 / 1 个 |

上游网关负责真实货币预算，Labs 不复制模型价格表。为保持 P4-004 合同一致，调用前只预留
1 microUSD 占位，成功时按 0 结算；金额字段不作为费用报告。Token、请求、频率、并发和
熔断仍由 Labs 独立执行。

48,000 Token 覆盖主模型与回退模型各一次的最坏输入输出。主模型直接成功时按标准 usage
退款；只要实际调用回退模型，无论主模型是否返回可信 usage，都按 48,000 Token 下限结算。
页面显示的 usage 只代表最终成功模型，不作为策略账本的完整双模型费用报告。

## Preview 验收配置

Preview 固定 `TOKEN_FORGE_AI_BUDGET_MULTIPLIER=100`，只把三层每日 Token 与 microUSD
合同占位放大 100 倍：

| 边界                                    |                         Preview 配置 |
| --------------------------------------- | -----------------------------------: |
| 匿名用户 / Token Forge / 全站每日 Token | 9,600,000 / 120,000,000 / 240,000,000 |
| 匿名用户 / Token Forge / 全站每日成本占位 |                400 / 5,000 / 10,000 |

Production 固定使用倍率 `1`。倍率只允许 `1` 或 `100`，其他值失败关闭。Preview 的每日
请求 4/50/100、60 秒请求 1/6/10、并发 1/2/3、单请求 48,000 Token、熔断和预留有效期均
保持生产值；因此放大预算不会绕过防突发流量和故障扩散的边界。100 倍策略只由
Preview 专属账本工厂基于已经通过共享 Schema 的 Production 策略派生，不能作为共享
策略配置重新输入，因而不会抬高 Production 的合同硬上限。

## 匿名用户边界

策略层只接受形如 `anon_<32-64 个安全字符>` 的 `actor_key`。P1-008 只使用 Cloudflare
Edge 提供的 `CF-Connecting-IP`，在服务端用独立 Secret 做 HMAC-SHA256 并编码为
`anon_<base64url>`。原始 IP 只在单次请求中短暂存在，不能使用 Cookie、User-Agent、邮箱
或仓库标识。密钥、原始标识与映射关系不得进入策略快照。

`actor_key` 是滥用控制标识，不是登录账户，也不能用于跨产品画像。公开响应不会返回它。

## 准入、预留与结算

每个请求执行以下状态机：

1. 验证固定 `lab_id`、`operation`、UUID、匿名用户键、服务端时间和预留额；
2. 清理过期预留与限流窗口，拒绝时间回退和重复 `request_id`；
3. 依次检查熔断、滑动限流、并发和 UTC 日预算；
4. 在调用 Provider 前，按最坏情况同时预留 Token 和微美元，并增加请求次数；
5. 成功后用服务端汇总的所有 Provider 尝试实际 Token 与成本结算，退回未使用差额；
6. Gateway 失败、进程中断或 60 秒未结算时保留全额预留，防止通过崩溃、超时或重试绕过
   成本上限；
7. 实际用量超过预留时失败关闭、保留全额预留，并把该次执行记为熔断失败。

重复请求 ID 不会再次预留。已结算 ID 保留 24 小时的有限去重标记；重复结算是幂等空操作。
日请求数不会因成功结算而退回，避免用大量低 Token 请求绕过频率边界。

## 熔断

以下调用后失败会增加连续失败数：

- Provider 限流或预算拒绝；
- Provider 超时或不可用；
- Provider 响应无效、截断或超大小；
- 输出命中安全策略；
- Gateway 内部失败。

连续 5 次后，`token-forge.plan-v1` 熔断 60 秒。到期后只允许一个半开探针：成功则关闭并
清零连续失败；失败或预留超时则重新打开。输入合同错误和请求体超限不代表 Provider
故障，不计入熔断。

## 安全失败映射

| 内部拒绝                      | Gateway 错误码         | 页面行为                 |
| ----------------------------- | ---------------------- | ------------------------ |
| 日 Token、成本或请求预算耗尽  | `budget_exhausted`     | 保留模板计划             |
| 滑动限流或并发已满            | `rate_limited`         | 保留模板计划，可稍后重试 |
| 熔断已打开或探针占用          | `provider_unavailable` | 保留模板计划，可稍后重试 |
| 时间回退、无效上下文或重复 ID | `invalid_request`      | 保留模板计划             |

公共失败只包含错误码、是否可稍后重试、最多 3,600 秒的 `retry_after_seconds` 和
`attempt_count: 0`。内部作用域、匿名用户键、原始错误、请求正文和预算快照不会返回浏览器。

## 状态与持久化边界

策略快照只允许：

- UTC 日桶中的 Token、微美元和请求计数；
- 不可逆匿名用户键；
- 请求 UUID、时间戳和预留数值；
- 限流时间戳与熔断状态。

快照有 256 KiB 上限、字段白名单、记录数上限和时间单调校验。目标、Prompt、计划、仓库
URL、Owner、文件路径、正文、IP、Cookie、User-Agent、Provider 原始错误和密钥都不在合同
内。

P1-008 使用 SQLite Durable Object 在单个事务内完成“读取快照 → 准入或结算 → 写回快照”，
Provider 网络调用位于准入和结算事务之间。目标、Prompt、摘要和计划不会进入 Durable
Object。

## 验证

合成测试覆盖：

- 策略 Schema、未知字段、硬上限和作用域顺序；
- Token、微美元、请求、滑动窗口和并发边界；
- 成功退款、失败全额计费、超时预留和重复请求；
- 关闭、打开、单探针半开、恢复和重新打开；
- 快照恢复、时间回退、敏感字段缺失和安全 Gateway 失败；
- 无网络、日志或持久化副作用。

测试不使用真实用户标识、仓库内容、Provider、价格、密钥或生产数据。

## P1-008 激活清单

代码已完成运行时、HMAC 匿名键、固定 Provider/模型/指令、最坏 Token 预留、usage 结算、
模板降级和合成测试。真实流量激活仍必须按顺序完成：

1. 分别为 Preview 设置 Provider Key 与匿名键 Secret；
2. 确认 `api-gpt.speedtest.margrop.net` 为 DNS-only，或把上游迁移到支持的 HTTPS 端口；
3. 部署 Preview，验证有效调用、模板路径、限流、无效输出和浏览器无密钥；
4. 人工确认 Preview 后，设置 Production Secrets 并手动触发 Production；
5. Production smoke 通过后，再把 P1-008 标记为完成。
