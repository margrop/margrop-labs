# Token Forge AI 流量与成本策略

P4-004 为 `token-forge.plan-v1` 定义 Provider-neutral 的预算、滑动限流、并发预留和熔断
核心。实现位于 `@margrop-labs/ai-gateway/token-forge-policy`，只操作经过验证的内存状态，
不创建 HTTP 端点、Provider Adapter、密钥、数据库或部署配置。

策略合同由
[`token-forge-ai-policy-v1.schema.json`](../schemas/token-forge-ai-policy-v1.schema.json)
约束。P1-008 必须先通过这层准入，再调用 Provider；任一拒绝都沿用 AI Gateway 的安全失败
信封并保留确定性模板计划。

## 固定硬边界

| 边界 | 默认硬上限 |
| --- | ---: |
| 单个 Gateway 请求可计费 Token | 56,000 |
| 单个 Gateway 请求成本 | $0.10 |
| 匿名用户每日 Token | 224,000 |
| Token Forge 每日 Token | 2,240,000 |
| 全站每日 Token | 5,600,000 |
| 匿名用户每日成本 | $0.25 |
| Token Forge 每日成本 | $5.00 |
| 全站每日成本 | $10.00 |
| 匿名用户 / Token Forge / 全站每日请求 | 12 / 200 / 400 |
| 60 秒内匿名用户 / Token Forge / 全站请求 | 2 / 20 / 40 |
| 匿名用户 / Token Forge / 全站并发 | 1 / 4 / 6 |
| 预留有效期 | 60 秒 |
| 连续失败后熔断 | 5 次 |
| 熔断打开时间 | 60 秒 |
| 半开探针 | 1 个 |

微美元是整数成本单位：`1 USD = 1,000,000 microUSD`，避免浮点金额累计误差。56,000
Token 覆盖 AI Gateway 最多两次 Provider 尝试的最坏情况，而不是只覆盖最终成功的一次。
P1-008 的服务端价格表必须用固定模型价格和最大尝试次数计算预留 Token 与预留成本；浏览器
不能提交价格、模型、预留额或结算用量。

运行配置只能收紧 Schema 中的预算、频率、并发和失败阈值，不能扩大上述硬边界。若调整真实
模型、最大尝试次数或价格，必须先验证单次成本上限仍覆盖最坏情况，再发布配置。

## 匿名用户边界

策略层只接受形如 `anon_<32-64 个安全字符>` 的 `actor_key`。它必须由 P1-008 在服务端
通过签名匿名会话或带密钥的不可逆摘要派生，不能使用原始 IP、Cookie、User-Agent、邮箱或
仓库标识。密钥、原始标识与映射关系不得进入策略快照。

`actor_key` 是滥用控制标识，不是登录账户，也不能用于跨产品画像。公开响应不会返回它。

## 准入、预留与结算

每个请求执行以下状态机：

1. 验证固定 `lab_id`、`operation`、UUID、匿名用户键、服务端时间和预留额；
2. 清理过期预留与限流窗口，拒绝时间回退和重复 `request_id`；
3. 依次检查熔断、滑动限流、并发和 UTC 日预算；
4. 在调用 Provider 前，按最坏情况同时预留 Token 和微美元，并增加请求次数；
5. 成功后用服务端汇总的所有 Provider 尝试实际 Token 与成本结算，退回未使用差额；
6. Gateway 失败、进程中断或 60 秒未结算时保留全额预留，防止通过崩溃、超时或重试绕过
   成本上限；
7. 实际用量超过预留时失败关闭、保留全额预留，并把该次执行记为熔断失败。

重复请求 ID 不会再次预留。已结算 ID 保留 24 小时的有限去重标记；重复结算是幂等空操作。
日请求数不会因成功结算而退回，避免用大量低 Token 请求绕过频率边界。

## 熔断

以下调用后失败会增加连续失败数：

- Provider 限流或预算拒绝；
- Provider 超时或不可用；
- Provider 响应无效、截断或超大小；
- 输出命中安全策略；
- Gateway 内部失败。

连续 5 次后，`token-forge.plan-v1` 熔断 60 秒。到期后只允许一个半开探针：成功则关闭并
清零连续失败；失败或预留超时则重新打开。输入合同错误和请求体超限不代表 Provider
故障，不计入熔断。

## 安全失败映射

| 内部拒绝 | Gateway 错误码 | 页面行为 |
| --- | --- | --- |
| 日 Token、成本或请求预算耗尽 | `budget_exhausted` | 保留模板计划 |
| 滑动限流或并发已满 | `rate_limited` | 保留模板计划，可稍后重试 |
| 熔断已打开或探针占用 | `provider_unavailable` | 保留模板计划，可稍后重试 |
| 时间回退、无效上下文或重复 ID | `invalid_request` | 保留模板计划 |

公共失败只包含错误码、是否可稍后重试、最多 3,600 秒的 `retry_after_seconds` 和
`attempt_count: 0`。内部作用域、匿名用户键、原始错误、请求正文和预算快照不会返回浏览器。

## 状态与持久化边界

策略快照只允许：

- UTC 日桶中的 Token、微美元和请求计数；
- 不可逆匿名用户键；
- 请求 UUID、时间戳和预留数值；
- 限流时间戳与熔断状态。

快照有 256 KiB 上限、字段白名单、记录数上限和时间单调校验。目标、Prompt、计划、仓库
URL、Owner、文件路径、正文、IP、Cookie、User-Agent、Provider 原始错误和密钥都不在合同
内。

P4-004 只提供可序列化状态机。P1-008 必须在单个原子持久化边界内完成“读取快照 → 准入或
结算 → 写回快照”，否则多实例并发会突破预算。刚完成连接、部署或迁移时也不能把空内存
Ledger 当成生产预算存储。

## 验证

合成测试覆盖：

- 策略 Schema、未知字段、硬上限和作用域顺序；
- Token、微美元、请求、滑动窗口和并发边界；
- 成功退款、失败全额计费、超时预留和重复请求；
- 关闭、打开、单探针半开、恢复和重新打开；
- 快照恢复、时间回退、敏感字段缺失和安全 Gateway 失败；
- 无网络、日志或持久化副作用。

测试不使用真实用户标识、仓库内容、Provider、价格、密钥或生产数据。

## P1-008 接入清单

P1-008 仍需完成：

1. 选择服务端运行时和原子持久化适配器；
2. 通过服务端秘密派生可轮换匿名用户键；
3. 固定 Provider、模型、指令、价格表和最大尝试次数；
4. 在每次 Provider 调用前预留所有尝试的最坏成本；
5. 汇总每次 Provider 尝试的可信可计费用量后结算；
6. 把预算、限流和熔断失败接回 P1-004 的模板降级；
7. 使用合成 Provider 做并发、重启、跨 UTC 日期和故障恢复测试；
8. 经过 Preview 验证后再由人工触发 Production 发布。

在这八项完成前，正式页面不得调用真实模型。
