# Incident Detective 逐步取证页面

P2-003 将 P2-002 的公开 `mysql-leading-wildcard` 场景接入
`/incident-detective/`，提供无需登录、无需 AI、无需真实监控系统的完整离线取证流程。

## 页面流程

1. 页面在 Astro 构建期导入并验证公开 `scenario.json`；
2. 用户从 9 点预算开始，只能获取前置条件和剩余预算都满足的证据；
3. 获取后证据不可撤回或退款，避免先查看内容再换另一条路径；
4. 页面只展示初始事件和已获取证据对应的 `revealed` 时间线事件；
5. 用户选择怀疑服务，将已获取证据标记为支持或反证，并填写机制、信心和下一步；
6. 用户明确选择安全动作后，浏览器生成并重新验证 Attempt v1；
7. 页面展示验证后的 Attempt JSON，但不保存、不上传，也不评分。

重新开始本局会同时清空证据、预算、假设和验证结果。

## 确定性状态机

`incident-detective-session.ts` 将交互状态限制为：

- `scenario_id`；
- 按获取顺序记录的 `selected_evidence_ids`；
- 与证据成本精确一致的 `spent_budget`。

每次读取状态都会重新检查场景、证据 ID、重复项、前置顺序和预算。证据状态只有四种：

| 状态                  | 含义                         |
| --------------------- | ---------------------------- |
| `available`           | 前置条件满足且剩余预算足够   |
| `locked`              | 至少一份直接前置证据尚未获取 |
| `insufficient_budget` | 前置条件满足，但剩余预算不足 |
| `selected`            | 已获取并永久计入本局预算     |

状态机不提供单份证据撤销函数。用户若要改走另一条证据路径，必须明确重新开始整局。

## 证据渲染

公开证据按结构化类型渲染：

- Prometheus：查询、Series Label 和可键盘滚动的时间序列表格；
- Loki：低基数 Stream、时间、级别和合成日志正文；
- MySQL：只读查询与可横向滚动的结果表；
- Runbook：分节文档；
- Topology：节点与有向调用关系。

锁定或预算不足时只显示证据标题、用途、成本和原因，不在页面视觉层展开 Payload。公开场景本身
仍是可检查的合成数据，不承担保密标准答案的职责。

## Attempt 表单

表单使用原生 `textarea`、`select` 和 `checkbox`，收集：

- 至少 20 字的机制假设；
- 至少一个怀疑服务；
- 至少一份已获取的支持证据；
- 可选反证，且同一证据不能同时支持和反驳；
- 低、中、高信心；
- 至少 10 字的安全下一步；
- 用户计划采用的安全或高风险动作。

状态机自动把当前可见时间线按场景时间顺序写入 Attempt。最终对象仍通过 P2-001
`validateIncidentDetectiveAttempt`，因此未知引用、预算不一致、敏感文本、重叠证据角色和
越过解锁顺序都会失败关闭。

P2-003 不阻止用户在合成游戏中选择“重启、生产写入、删除”等高风险动作，因为这些选择要由
P2-004 评分；页面会明确标注其生产风险和审批要求，且不会执行任何真实操作。

## 客户端数据边界

页面只导入：

`labs/incident-detective/cases/mysql-leading-wildcard/scenario.json`

以下文件不会进入页面源码或静态构建：

- `answer.internal.json`；
- `attempt.canonical.json`；
- 内部答案 Schema；
- 未来 P2-004 的评分规则。

测试同时扫描页面、组件、状态机和静态 HTML，拒绝内部答案路径与字段。浏览器端没有
`fetch`、Local Storage、Analytics、AI Provider 或数据库连接。

## 可访问性与移动端

- 所有操作使用原生按钮、表单、`progress`、`details`、列表和表格；
- 动态结果使用现有 `StatusNotice` 的 `status` / `alert` 语义；
- 锁定原因和按钮通过 `aria-describedby` 关联；
- 表格容器可获得键盘焦点并横向滚动；
- 支持 320px 宽度，证据、选项、时间线和结果摘要在窄屏重排；
- 控件最小高度遵循 44px 基线；
- 全局 reduced-motion 和 forced-colors 合同继续生效。

## 测试与已知限制

自动化覆盖证据解锁、不可退款、预算耗尽、时间线揭示、Attempt 生成、敏感文本、无副作用、
内部答案隔离、静态页面内容、原生控件与响应式 CSS。

当前不包含：

- 根因或取证顺序评分；
- 标准答案展示；
- AI 解释与案例变体；
- Attempt 持久化或分享；
- 真实 Prometheus、Loki、MySQL 接入。

这些能力分别留给 P2-004、P2-005 和 P2-006；P2 首版继续只使用仓库内合成数据。
