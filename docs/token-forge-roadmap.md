# Token 任务炼金炉优先路线图

## 战略

从 2026-07-25 起，Token 任务炼金炉是 Margrop Labs 唯一的产品开发主线。现有 AI
故障侦探和 SMART / RMA 报告机保留可访问、可构建、可修复的状态，但在 Token Forge
达到本文件的完成门槛前，不继续增加功能。

以下事项可以打断主线：

1. 生产故障、数据泄露或高危依赖漏洞；
2. 阻塞 Token Forge 发布的公共平台能力；
3. 仓库所有者明确改变优先级。

许可证选择仍由仓库所有者决定。与 Token Forge 无关的重构、设计升级、AI 能力和增长实验
均不能借公共平台名义插队。

## 当前差距

Token Forge 已有版本化输入/计划合同、确定性模板、公开 GitHub 仓库摘要适配器、
Provider-neutral AI 规划核心、Markdown / GitHub Issue 导出核心和可用的 Alpha 页面。

当前页面已接通“输入 → 本地模板/AI 增强 → 导出”路径和可选的公开仓库覆盖证据；仓库或
AI 失败不会阻断模板。P1-008 已提供固定 OpenAI-compatible Adapter、HMAC 匿名限流、
SQLite Durable Object 原子状态与页面 AI 入口，并已通过 Preview 真实链路验收；Provider
usage 不再作为本地额度账本的可信输入。当前等待人工 Production 激活。用户还不能编辑、
锁定和重排计划，也没有面向 Coding Agent 的完整执行
包、端到端质量基准或真实转化数据。因此产品主流程接近走通，但完整闭环仍未完成。

## “特别完善”的完成门槛

只有同时满足以下五类门槛，Token Forge 才视为达到当前战略要求：

### 1. 完整用户闭环

- 无需登录、无需 AI 的合成样例始终可用；
- 可选公开 GitHub 仓库可以产生覆盖报告，并明确显示已读取、已忽略和未知项；
- 用户可以在模板或 AI 计划上锁定、删除、排序、调整预算并重新验证；
- 每个任务包含目标、范围、非目标、依赖、验收、测试、风险和 Agent Prompt；
- 可以导出完整计划、逐任务 Issue 草稿和与具体 Provider 无关的 Coding Agent 执行包。

### 2. 计划质量

- Schema、依赖图、Token 总额和工时预算的确定性验证通过率为 100%；
- 至少 30 个合成基准场景覆盖不同 Token 档位、技术栈、仓库规模和失败路径；
- 基准中至少 90% 的计划不含无法验收的空泛任务，剩余任务必须被质量规则标为需人工修改；
- 每个排序和降级结果都能指向明确规则、预算或仓库覆盖证据。

### 3. 隐私、成本与可靠性

- 仓库 URL、路径、文件正文、表单目标和计划正文不进入 URL、Analytics 或服务日志；
- AI 只接收版本化 allowlist 投影，Secret 与疑似 Secret 失败关闭；
- 单次、单日和单用户预算、超时、重试、限流和熔断均有硬上限；
- 网络、GitHub、AI、Schema 或导出失败时，页面保留可用模板结果和明确恢复路径；
- CI、端到端测试、Production smoke test 和回滚说明全部通过。

### 4. 产品体验

- 首次用户不阅读仓库文档也能在 3 分钟内完成样例生成和一次导出；
- 320px 手机宽度、键盘操作、reduced motion 和错误恢复路径通过检查；
- 页面清楚区分模板结果、仓库证据、AI 增强、未知项和用户修改；
- 不存在不可运行的按钮、伪造的分析结果或依赖真实凭据的演示。

### 5. 上线证据

- 连续观察至少 14 天；
- 在最小事件口径下累计至少 50 次有效运行和 10 次导出；
- 没有确认的敏感正文采集事件、P0/P1 未解决缺陷或失控 AI 成本；
- 完成 P4-008 复盘，并由仓库所有者明确批准解除其他 Lab 的功能冻结。

真实使用量不足时继续改善 Token Forge 的入口、样例和核心价值，不以开发新 Lab 代替验证。

## 冻结规则

- P2 已完成的 MVP 保留维护，不新增案例、AI 能力或分享功能；
- P3-004 至 P3-006 保持冻结，不继续健康分类、AI 解释或 RMA 导出；
- 新 Lab 提案只记录问题与证据，不进入实现；
- 共用组件只有在 Token Forge 当前任务确实需要时才允许扩展；
- 安全修复可以立即处理，但必须保持边界清晰，并在完成后返回上述执行顺序。
