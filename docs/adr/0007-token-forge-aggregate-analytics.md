# ADR-0007：Token Forge 最小聚合 Analytics

- 状态：Accepted
- 日期：2026-07-27

## 背景

Token Forge 的核心生成、编辑和导出闭环已经稳定，需要为 P4-008 与 Beta 出口评审提供
至少 14 天的打开、运行、导出及文章/源码点击趋势。同时，表单目标、技术栈、仓库 URL、
公开仓库摘要、计划、导出和错误都可能包含用户或项目上下文，不能为了统计转化扩大正文
采集面。

P1-006 已冻结 `token-forge-event-v1`：只允许固定事件、Lab ID、Lab 版本和粗粒度设备
类别。ADR-0003 要求引入新的持久化方案前记录架构决策。

## 决策

1. 浏览器只向同源 `POST /api/token-forge/events` 发送通过
   `token-forge-event-v1` allowlist 与 Schema 的五个字段。
2. 请求使用 `credentials: "omit"`、`referrerPolicy: "no-referrer"`、`keepalive: true`
   且不重试；上报失败或异步拒绝不会影响生成、编辑、导出与页面导航。
3. Worker 只接受同源、JSON、最大 1 KiB 的 POST。未知字段在事件边界丢弃；无效来源、
   方法、媒体类型、大小或合同安全失败，响应不回显请求内容。
4. 使用独立的 SQLite Durable Object 和固定对象名串行聚合，不与 AI 预算/熔断状态共用
   namespace 或快照。
5. 每个事件在同一存储事务内立即折叠为“UTC 日期 × 事件枚举 × 粗粒度设备类别”的整数
   计数。持久化合同为 `token-forge-analytics-snapshot-v1`。
6. 只保留当前 UTC 日及之前 30 天，最多 31 天、每天最多 24 个计数。计数达到 JavaScript
   安全整数上限后保持上限，不创建溢出值。
7. 不创建原始事件表、访客/会话 ID、单次时间戳、来源页面、referrer、User-Agent 或网络
   标识；不读取或保存 IP、域名、主机名。
8. 不保存表单值、技术栈、目标、仓库 URL、覆盖计数、路径、文件正文、Prompt、Response、
   计划、导出内容、错误正文、输入长度或性能细节。
9. 当前不提供公共或浏览器可用的统计读取 API。P4-008 若需要报表，必须另行增加仅所有者
   可访问的最小投影和认证边界；不能通过公开 GET 暴露生产计数。
10. Preview 与 Production 使用同名、环境隔离的 Durable Object binding；Production
    发布仍保持人工触发。部署 smoke 只提交无效空合同并期望 `400`，不污染真实计数。
11. Analytics 不调用模型、不消耗 AI Token。成本仅为小于 1 KiB 的请求和一个有界
    Durable Object 快照事务。
12. 这些计数是事件次数，不是唯一用户数。刷新、重复操作、自动化或伪造同源 Header 的
    非浏览器请求可能放大计数，因此 P4-008 只能把它作为方向性漏斗，并结合博客侧数据和
    线上异常检查解释。

## 后果

- P4-008 可按天计算打开、成功/失败运行、导出、返回文章和 GitHub 点击次数；
- 31 天窗口覆盖 14 天出口证据并限制存储增长；
- 客户端没有 Cookie、用户身份和自由文本，服务端没有可回放的单次行为；
- 无法计算唯一访客、跨日留存、精确来源或逐次运行链路；
- 仅凭 Token Forge 事件不能区分“从博客进入”与直接打开；P4-005/P4-006 的博客入口数据
  需要在复盘时单独提供；
- 公共端点可能被机器人或脚本污染，不能把计数当作计费、安全或业务审计依据。

## 备选方案

### Cloudflare Web Analytics 或全站自动采集

拒绝。自动采集的页面、referrer、User-Agent 与平台处理边界超出当前五字段合同，也无法
保证只覆盖 Token Forge 的明确事件。

### 保存每条原始事件后离线聚合

拒绝。即使字段很少，单次时间戳和请求元数据仍会形成可关联行为记录，且存储随流量增长。

### D1

暂不采用。当前只有一个 Lab、一个短窗口和一个小快照，单对象事务更简单。未来确需跨 Lab
分析时，必须从聚合快照派生新的最小投影，不能回补原始事件。

### 进程内 Map

拒绝。隔离实例和重启会丢失统计，也无法保证并发写入正确。
