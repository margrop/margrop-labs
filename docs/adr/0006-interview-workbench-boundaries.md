# ADR-0006：AI 面试工作台边界与公共 AI 能力复用

- 状态：Accepted
- 日期：2026-07-28

## 背景

仓库所有者决定暂停 SMART / RMA 报告机的后续产品开发，用 AI 面试工作台替代其产品位置，
并把新项目设置为 Token 任务炼金炉之后的第二优先级。新项目需要处理简历、岗位 JD 和
面试记录，输入比公开仓库上下文更敏感，同时包含三类可组合 AI 操作：

1. 根据简历与 JD 判断岗位匹配度；
2. 根据简历与 JD 生成完整面试计划；
3. 根据面试记录生成面试结论草稿。

Token Forge 已验证 Provider-neutral Gateway、脱敏、预算、限流、熔断、固定主/回退模型、
Cloudflare Worker 和自定义端口传输。若每个 Lab 再复制一套，会造成安全策略漂移。

## 决策

### 产品边界

1. 同一产品支持 `interviewer` 与 `candidate` 两种模式，二者共享事实和证据合同，但输出
   目的不同：面试官获得评价辅助，面试者获得准备与复盘建议。
2. 主流程固定为“匹配分析 → 面试计划 → 面试记录与结论”，每一步都可以重新编辑、验证和
   导出；后一步只能引用前一步已经验证的结构化 ID。
3. 匹配结果必须区分明确支持、部分支持、未提供证据、冲突和不适用。缺失信息不得被自动
   推断为能力不足。
4. 面试计划支持 30/45/60 分钟和可选的前置快速判断段；每个问题都必须绑定考察目标、
   证据期望、追问、评分锚点和时间预算。
5. 面试结论只能由结构化记录产生，必须显示证据、反证、未覆盖项和 AI 推断。AI 输出是
   可编辑草稿，不能自动作出录用或淘汰决定。

### 安全与公平边界

1. 简历、JD 和面试记录均为 `sensitive`。原文默认只存在于当前浏览器会话，不持久化、
   不进入 URL、Analytics、日志、错误追踪或分享卡。
2. 跨越浏览器边界前先执行操作专属允许字段映射，再使用公共脱敏包；姓名、联系方式、
   住址、证件、账号和 Secret 不进入 AI 请求。
3. AI 和确定性规则均不得使用或推断年龄、性别、婚育、民族、健康、宗教、政治倾向等
   受保护信息，不得进行人格或心理诊断。
4. 输出必须保留未知项和人工确认状态；“AI 未发现证据”不等于“事实不存在”。
5. 合成样例不包含真实个人、公司内部 JD 或面试记录，只使用 `example.com` 标识。

### 公共 AI 能力复用

复用公共层，不复制 Token Forge 业务运行时：

- `@margrop-labs/ai-gateway`：请求/响应信封、硬上限、错误码、Provider Adapter、
  超时、有限重试和结构化输出验证；
- `@margrop-labs/redaction`：允许字段优先、个人标识脱敏和 Secret 默认拒绝；
- Cloudflare Worker：服务端 Secret、固定 OpenAI-compatible Provider、TLS TCP 传输、
  主模型 `qwen-latest` 与回退模型 `minimax-latest`；
- Durable Object 策略模式：按 `lab_id + operation` 隔离预算、匿名限流、并发和熔断；
- UI、导出、可访问性、CI、Schema/fixture 和五类隐私 sink 测试。

面试业务新增独立版本化操作，暂定：

- `interview.match-v1`
- `interview.plan-v1`
- `interview.conclusion-v1`

每个操作拥有独立输入投影、输出 Schema、Prompt、Token 上限和降级结果。浏览器不能选择
Provider、模型、Prompt、重试次数或预算。现有 `token-forge-*` 环境变量、端点和 Durable
Object 名称不直接复用；开始 P5-006 时先抽取通用运行时外壳，再分别注册 Token Forge 与
Interview Workbench，保证现有 Production 行为不变。

### 优先级

本 ADR 和 Proposed Manifest 只记录已批准的产品方向，不解锁功能开发。Token Forge 仍按
既定路线图完成 P4-003、P4-005 至 P4-008 和 P1-014。P1-014 通过后，默认只解锁 AI
面试工作台；AI 故障侦探与 SMART / RMA 继续冻结，除非仓库所有者再次明确调整优先级。

## 后果

- 新 AI 项目可以把精力集中在岗位匹配、问题设计和证据化结论，而不是再次实现密钥、
  Provider、限流、熔断和传输；
- 面试数据需要比 Token Forge 更严格的本地处理和公平性测试；
- 提取通用运行时必须保持 Token Forge 端点、Secrets、预算账本和失败行为兼容；
- 新项目现在会出现在首页第二位并显示“规划中”，但在完成可运行合成样例前没有可点击页面；
- SMART / RMA 现有 Alpha 页面继续可访问和维护，但不再进入功能开发队列。

## 备选方案

### 每个面试步骤单独做一个 Lab

拒绝。三步共享同一份要求、证据和会话引用，拆开会重复敏感输入并破坏可追溯性。

### 直接复制 Token Forge Worker

拒绝。Token Forge 当前端点、策略名和 Prompt 都是业务专属；复制会造成预算与安全修复漂移。

### 自动筛选或自动录用

拒绝。缺失证据、模型偏差和受保护属性风险使其不适合作为自动决策系统。本项目只提供
证据化辅助和可编辑结论草稿。
