# Token Forge 本地编辑、锁定与重新规划

P1-010 在模板或 AI 计划通过 Token Forge Plan v1 后，建立一个只存在于当前标签页的
`TokenForgeEditorSession 1.0`。它是页面内部状态，不改变公开输入或计划 Schema，也不新增
网络、模型、存储、日志或依赖。

## 可执行操作

- 编辑任务标题、规模、预计 Token、预计工时、包含范围、非目标、验收标准和 Agent Prompt；
- 锁定或解锁任务；锁定后禁止编辑、删除和移动该任务；
- 删除没有被其他任务依赖的任务，且计划至少保留一项；
- 将相邻的两个未锁定任务上移或下移；
- 调整整个计划的 Token 与工时上限；
- 在没有锁定任务时，重新使用确定性质量规则排序；
- 随时恢复本次生成的原始结果，清除本地修订、锁定与手动顺序。

任务 ID 和依赖在 P1-010 中保持只读。删除仍被依赖的任务会失败；移动后如果某项依赖不再
位于使用者之前，也会失败。页面显示修订次数和锁定数量，生成结果与用户修改结果使用不同
标签。

## 每次应用的验证链

编辑操作先在副本上完成，只有以下步骤全部通过才替换页面结果：

1. 自由文本经过字段 allowlist、长度限制、PII 脱敏和 Secret 拒绝；
2. 输入重新通过 Token Forge Input v1；
3. 计划重新通过 Plan v1、任务 ID、依赖图、Token 总额和工时上限；
4. 手动顺序重新检查依赖先行，并标记为 `QF-O04`；
5. 六项确定性质量规则重新评分；
6. Markdown 与 GitHub Issue 草稿从最终计划重新生成。

任何一步失败都会保留上一版计划，并显示不回显原始敏感值的稳定错误。修改不会自动再次
调用 AI；“AI 增强生成”仍是唯一的模型入口。

## 锁定与重新排序

锁定表示用户已确认该任务内容和当前位置。为避免“自动优化”覆盖这一决定，只要存在锁定
任务，“按质量重新排序”就不可用。全部解锁后，用户可以显式运行 P1-009 的依赖安全质量
排序；随后页面仍把最终顺序作为用户确认的本地版本继续编辑。

手动移动只交换相邻任务。不能移动到边界之外，不能跨过锁定任务，也不能形成依赖倒序。
依赖本身暂不支持编辑，避免在缺少依赖图可视化时引入难以察觉的计划语义变化。

## 隐私、成本与生命周期

- 编辑状态不写入 `localStorage`、数据库、日志、URL 或 Analytics；
- 页面刷新、关闭标签页或修改顶部生成表单都会清除本地编辑状态；
- PII 继续脱敏，Token、Cookie 和 Authorization 等 Secret 失败关闭；
- 本地操作不调用 GitHub、AI Gateway 或 Provider，因此没有新增 Token 成本；
- “恢复生成结果”只恢复当前标签页内保留的基线，不提供跨设备或跨会话历史。

P1-011 将在这个已重新验证的最终计划上生成 Provider-neutral Coding Agent 执行包。
