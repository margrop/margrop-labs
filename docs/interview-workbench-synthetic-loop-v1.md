# AI 面试工作台：无需 AI 的双角色合成闭环 v1

P5-005 把 P5-001 至 P5-004 的确定性能力串成一个可重复的本地样例。它同时生成面试官模式和
面试者模式，并让两种模式分别完成：匹配结果、30/45/60 分钟计划、记录、结论草稿和安全摘要
导出。整个闭环不读网络、不调用 AI、不要求登录，也不接触真实简历或 JD。

## 闭环输出

`buildInterviewSyntheticLoop(bundle)` 返回一个本地 `run`：

- `match`：同一份已验证的合成输入产生一份确定性岗位匹配结果；
- `roles.interviewer`：面试官计划、记录、结论和摘要导出；
- `roles.candidate`：面试者计划、记录、结论和摘要导出；
- `loop`：只保存两种角色的阶段 ID 和状态，便于工作台导航，不保存事实原文。

两种角色都使用 45 分钟合成计划。面试官记录会把直接证据转为支持信号，把未知要求保留为
unknown；面试者记录只复述合成的已有证据，未知项仍然是 unknown，`fabrication_allowed` 永远
为 `false`。所有记录和结论都是 `draft`，必须人工确认。

## 安全摘要导出

`interview-export-v1` 只允许导出结构化计数和枚举：匹配区间、计划时长、记录条数、结论状态、
人工确认状态和固定的 `redacted_fields`。它不会导出：

- 简历、JD、问题或追问正文；
- 候选人陈述、面试官观察、事实和反证文本；
- 姓名、联系方式、其他个人标识或 Provider 元数据。

导出仍标记为 `sensitivity: "sensitive"` 和 `local_only: true`，因为汇总状态可能涉及敏感招聘
判断。用户主动触发下载前应展示这些字段；系统不自动发布、不持久化，也不把摘要当作录用或淘汰
决定。Markdown 渲染器同样只消费这个摘要合同，不接受原始记录对象。

## 验收边界

- 两种角色都通过 Match/Plan/Record/Conclusion 的现有引用和人工确认校验；
- 角色阶段 ID、导出 ID 和 `match_id` 必须闭合且全局唯一；
- 结构化摘要的记录和结论计数必须精确闭合；
- 无效字段、个人文本或自动决定标记会失败关闭，错误不回显输入值；
- P5-007 已将这个纯函数闭环接入 `/interview-workbench/` 页面；页面仍以合成样例和 noindex
  方式开放，真实输入和 Alpha 出口留给后续基准与评审。
