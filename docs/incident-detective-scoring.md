# Incident Detective 确定性证据评分

P2-004 为 `/incident-detective/` 增加本地、可审核的评分链路。分数由代码和版本化规则计算，
AI 不参与事实判断、自由文本理解或分数调整。

## 三层边界

评分数据分成三层：

1. `scenario.json` 是公开事故、证据与时间线，不包含答案、权重或 rubric；
2. `score-rules.internal.json` 是案例专属规则，只引用结构化证据、服务、顺序和安全动作；
3. `incident-detective-score-v1.schema.json` 是公开结果合同，只输出总分、等级、维度、逐条判定
   与反馈。

`answer.internal.json` 与 `attempt.canonical.json` 只供仓库测试和案例审核，页面和评分模块都不
导入。规则文件会随静态客户端发布，因此规则是可检查的游戏机制，而不是保密答案。

## 评分流程

`scoreIncidentDetectiveAttempt` 按固定顺序处理：

1. 重新验证 Scenario；
2. 重新验证 Attempt 的引用、预算、解锁顺序和隐私边界；
3. 验证规则 Schema、场景 ID、唯一 ID、引用、维度上限与总分；
4. 逐条执行确定性规则；
5. 将每个维度限制在 `0..max_score`；
6. 汇总 0–100 总分和等级；
7. 重新验证公开 Score v1 结果及其分数对账。

任一步失败都不产生部分分数。评分函数不访问网络、存储、日志、时间或随机数，相同三份输入
始终得到相同结果。

## 首案五个维度

| 维度     | 上限 | 只检查的结构化信号                                         |
| -------- | ---: | ---------------------------------------------------------- |
| 证据覆盖 |   35 | 关键指标、Trace、只读查询计划、连接压力、反证与上下文      |
| 取证顺序 |   20 | 拓扑/健康/延迟/Trace/查询计划之间的先后关系                |
| 结论覆盖 |   20 | 怀疑服务范围，以及关键证据是否被标记为支持                 |
| 反证意识 |   10 | 是否明确标记至少一份合理反证                               |
| 安全边界 |   15 | 只读、保留证据、最低权限、审批，以及重启/写入/删除风险扣分 |

五个维度的正向规则上限必须恰好合计 100。高风险动作使用负分规则，但单个维度不会低于 0。
canonical attempt 用于证明一条可达、安全且包含反证的路径可以获得 100 分，不会发送到客户端。

## 等级

| 分数   | 稳定值           | 页面文字 |
| ------ | ---------------- | -------- |
| 0–39   | `needs-evidence` | 证据不足 |
| 40–69  | `developing`     | 正在形成 |
| 70–94  | `evidence-led`   | 证据驱动 |
| 95–100 | `excellent`      | 完整闭环 |

等级阈值位于评分代码中，不由 AI 或用户输入决定。

## 有意不评分的内容

v1 不对以下内容做语义判断：

- 根因摘要的措辞是否与标准答案相似；
- “下一步”自由文本是否包含特定关键词；
- 信心级别是否主观合理；
- 未结构化表达中的技术深度或写作质量。

这些字段仍通过长度、隐私和引用合同验证。未来 AI 可以解释已生成的结构化结果，但不能改写
规则命中状态、维度得分或总分。

## 规则不变量

仓库内部规则 Schema 与 TypeScript 验证器共同保证：

- 维度和规则 ID 全局唯一；
- 所有证据、服务和动作引用都属于当前场景或受支持枚举；
- 每个维度的正向规则之和等于该维度上限；
- 所有维度上限之和等于 100；
- 顺序规则不能把同一证据与自己比较；
- 安全动作规则只能位于安全维度；
- 规则与反馈文本继续通过合成数据和敏感内容边界。

公开 Score v1 结果还会对账 Findings、维度、总分与等级，并拒绝额外字段，避免把内部权重、
标准答案或 Attempt 自由文本放入可分享结果。

## 自动化验收

测试覆盖 canonical 100 分、顺序变化、缺失反证、危险动作扣分、低证据路径、重复运行、
Schema/引用/总分错误、敏感反馈、公开 Scenario 无评分字段、公开结果拒绝权重，以及无网络、
存储和日志副作用。静态构建检查还确认评分标识、五个维度、按需加载和内部答案隔离。
