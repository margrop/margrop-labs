# AI 面试工作台路线图

## 产品目标

用一条连续、可追溯的工作流完成：

```text
简历 + 岗位 JD
  → 要求—证据匹配
  → 30/45/60 分钟面试计划
  → 结构化面试记录
  → 有证据、反证和未知项的结论草稿
```

面试官模式帮助尽早发现不匹配并提高面试一致性；面试者模式帮助识别差距、准备真实项目
证据和复盘表现。两种模式都不允许伪造经历或把 AI 判断伪装成事实。

## 优先级

1. Token 任务炼金炉仍是唯一产品开发主线；
2. AI 面试工作台是 Token Forge Beta 出口后的第二优先级；
3. AI 故障侦探保留已完成 MVP，只做维护；
4. SMART / RMA 报告机暂停并退出后续产品开发序列，只做维护。

本文件的任务原本在 P1-014 通过前均保持阻塞；2026-07-28，仓库所有者明确批准绕过 Token
Forge 真实观察门槛的风险例外，因此解锁 P5-001。该例外只授权 AI 面试工作台继续实现，
不把 Token Forge 的 Beta 评审改为通过，也不放宽面试项目的隐私、公平和人工确认边界。

## 三类核心合同

### 1. 岗位匹配

维度至少包含：

- 必备条件与明确门槛；
- 技术技能与工具；
- 领域和业务经验；
- 项目复杂度、职责范围与职级；
- 沟通、协作等只能由具体经历支持的能力；
- 证据缺口、冲突和需面试验证项。

每项必须引用 JD requirement ID 和 resume evidence ID。总体结果只允许从已验证维度聚合；
AI 不能凭语气、学校、公司知名度或受保护信息暗示能力。

### 2. 面试计划

计划支持 30/45/60 分钟，默认建议 45 分钟：

- 5 分钟：开场和职责确认；
- 10–15 分钟：前置关键门槛，允许面试官根据明确规则提前结束；
- 15–25 分钟：项目、技术和问题解决深挖；
- 5–10 分钟：反向提问、遗漏补充和结束。

每个问题包含考察目标、关联要求、主问题、追问、正向/风险信号、评分锚点和分钟预算。
提前结束只能基于用户预先选择的必备门槛和面试证据，不能由模型自由决定。

### 3. 面试记录与结论

记录以问题和 requirement ID 为索引，区分：

- 候选人明确陈述；
- 面试官观察；
- 可验证证据；
- 反证或矛盾；
- 未提问、未回答和需后续确认。

结论输出维度判断、整体建议、强项、风险、证据不足项和后续动作。每条判断必须引用记录；
AI 结论默认为 `draft`，只有用户显式确认后才能导出为最终版。

## AI 运行时复用计划

公共层已经可以复用信封、验证、脱敏、错误、上限和 Provider Adapter。P5-006 只做一次
向后兼容抽取：

1. 把 Token Forge 专属 Worker 路由外壳拆成通用 `lab_id + operation` 注册表；
2. 保持现有 `/api/token-forge/plan`、Secret、模型、预算和回退行为完全不变；
3. 为 Interview Workbench 注册独立端点、Prompt、输入/输出验证器和策略命名空间；
4. 共用自建 OpenAI-compatible Provider 与 DDNS 主机名，不固定其每日变化的公网 IP；
5. 继续使用 `qwen-latest` 主模型和 `minimax-latest` 回退模型，除非独立质量基准支持变更；
6. 上游网关负责真实货币预算，Labs 保留保守的 Token、频率、并发、超时和熔断上限。

## Alpha 出口门槛

- 两种角色都能在三分钟内跑通无需登录、无需 AI 的合成样例；
- 三类输出全部通过版本化 Schema、引用完整性和时间预算验证；
- AI、网络、限流、熔断和无效输出时仍保留规则化结果与安全导出；
- 姓名和联系方式不进入 AI、URL、Analytics、日志或错误追踪；
- 受保护属性、人格诊断和自动录用/淘汰路径均有失败关闭测试；
- 320px、键盘、reduced motion 和主流程浏览器测试通过；
- 真实输入默认不持久化，导出必须由用户主动触发。
